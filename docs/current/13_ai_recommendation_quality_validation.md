# AI Recommendation Quality Validation

## 1. 문서 목적

이 문서는 AI 추천 결과가 규칙 기반 classification을 얼마나 보완하는지 검증하기 위한 current 문서다.

목적:

- HR 페르소나 기대값 대비 규칙 기반 추출 품질 확인
- HR 페르소나 기대값 대비 AI 추천 품질 확인
- 규칙 기반 + AI 추천 합산 효과 확인
- AI 추천 오추출 항목 확인
- classification phase 3 개선 우선순위 도출
- 선택 반영 기능을 실제 정제 흐름에 사용해도 되는 수준인지 판단

## 2. 현재 기준 상태

- 규칙 기반 classification은 config와 deterministic rule 기반으로 동작한다.
- AI recommendation은 openai mode에서 OpenAI 추천 결과를 생성할 수 있다.
- AI 추천 결과는 `ai_recommendation_runs` history에 저장할 수 있다.
- 저장된 AI 추천 결과는 frontend에서 목록, 상세, 비교, 선택 반영까지 가능하다.
- AI 추천은 자동 확정하지 않는다.
- 사용자가 선택한 skill/competency 항목만 `review_items`에 반영할 수 있다.
- 현재까지 문서상 규칙 기반 평균 매칭률은 약 56% 수준으로 기록되어 있다.
- AI 추천 품질은 아직 체계적으로 수치화하지 않았다.
- 실제 AI 추천 결과나 HR 기대값이 아직 없는 항목은 이 문서에서 `작성 예정` 또는 `사용자 입력 필요`로 둔다.

### 추가 검증 후보

추가 권장 공고 유형:

- 금융/핀테크
- 교육/에듀테크
- 문맥 의존 역량 표현이 많은 서비스기획/PM 공고
- 현재 config 커버리지가 약한 산업군

권장 총량:

- 기존 4개 + 추가 2~3개
- 총 6~8개 공고 기준으로 1차 방향성 판단

## 4. 검증 지표 정의

### 4-1. 규칙 기반 단독 매칭률

정의:

```text
규칙 기반 추출값 중 HR 페르소나 기대값과 매칭되는 항목 수 / HR 페르소나 기대값 총 항목 수
```

용도:

- 현재 deterministic classification 품질 확인
- config/rule 보강 필요 영역 파악

### 4-2. AI 추천 단독 매칭률

정의:

```text
AI 추천값 중 HR 페르소나 기대값과 매칭되는 항목 수 / HR 페르소나 기대값 총 항목 수
```

용도:

- AI 추천 자체의 커버리지 확인
- AI가 규칙 기반보다 문맥을 잘 잡는지 확인

### 4-3. 규칙 기반 + AI 추천 합산 매칭률

정의:

```text
규칙 기반 추출값과 AI 추천값을 합친 뒤 HR 페르소나 기대값과 매칭되는 고유 항목 수 / HR 페르소나 기대값 총 항목 수
```

주의:

- 중복 항목은 1회만 계산한다.
- 동일 의미 표현은 사람이 판단해 매칭 가능하다.
- 예: `요구사항 분석`과 `고객 요구사항 분석`은 같은 항목으로 볼 수 있다.

용도:

- AI가 규칙 기반을 얼마나 보완하는지 확인
- 목표 기준: 현재 56%에서 70% 이상으로 상승하면 실질 기여로 판단

### 4-4. AI 추천 오추출률

정의:

```text
AI 추천값 중 HR 페르소나 기대값에 없고 직무 관련성이 낮은 항목 수 / AI 추천 총 항목 수
```

오추출 예:

- 기획 직무에 불필요한 개발 기술 스택
- 회사 소개용 고유명사
- 고객사/기관명/인증명
- 포트폴리오 제출 등 전형 요건
- 태도/성향 표현 중 직무 역량으로 보기 어려운 항목

용도:

- prompt 개선 필요 여부 판단
- 선택 반영 전 필터링 필요 여부 판단

## 5. 매칭 판정 기준

### 매칭 인정

- 동일 표현
- 동의어 또는 같은 업무 개념
- 대표값과 alias 관계로 볼 수 있는 표현
- HR 페르소나 기대값과 업무 맥락이 같은 표현

| HR 기대값 | 서비스/AI 표현 | 판정 |
|---|---|---|
| 요구사항 분석 | 고객 요구사항 분석 | match |
| 정책 수립 | 운영 정책 수립 | match |
| 데이터 분석 | 사용자/운영 데이터 분석 | match |
| 와이어프레임 | UX/UI 와이어프레임 | match |

### partial 인정

- 넓은 개념은 맞지만 구체성이 부족한 경우
- 직무 맥락은 맞지만 대표값이 다소 넓거나 좁은 경우
- 사람이 보완 판단이 필요한 경우

### mismatch

- HR 기대값에 없는 항목
- 직무 수행과 직접 관련이 약한 항목
- 회사 소개/고유명사/전형 요건
- 기술스택이지만 해당 직무 직접 요구가 아닌 항목

## 7. 기존 4개 공고별 현재 검증 메모

### 누아 / 웹서비스 기획자

현재 관찰:

- 여행 산업/도메인, 서비스 기획, 요구사항 분석, 정책 수립은 원문과 부합한다.
- IA는 이번 공고에서 직무 수행 맥락 근거가 약해 오추출 가능성이 있다.
- IATA는 기관/인증명으로 skill 제외 후보다.
- AI 추천이 IA/IATA 같은 고유명사/약어를 어떻게 처리하는지 확인이 필요하다.

검증 포인트:

- 여행/항공권 유통 맥락을 산업/도메인으로 잘 잡는지
- 서비스 기획 역량을 과도하게 일반화하지 않는지
- IA/IATA 오추출 여부

### 세나 / 서비스 기획 주니어

현재 관찰:

- 헬스케어/EMR/HIS/OCS/UX/UI/스토리보드/와이어프레임 추출 개선이 확인되었다.
- `industry_category`는 null로 남았던 이력이 있다.
- 의료/SaaS/헬스케어 도메인 alias 검토가 필요하다.

검증 포인트:

- AI가 의료/헬스케어/SaaS 맥락을 잘 분리하는지
- EMR/HIS/OCS를 직무 관련 skill/domain으로 적절히 판단하는지
- 네이버/오름차트/클레 같은 고유명사를 제외하는지

### 슈퍼진 / 글로벌 서비스 기획/운영

현재 관찰:

- 규칙 기반 결과는 partial이다.
- 게임/콘텐츠 industry/domain null 이슈가 있었다.
- 와이어프레임, FAQ, VOC, 정책 수립, 운영 가이드, 서비스 운영, 프로젝트 리딩 등이 누락 후보다.

검증 포인트:

- AI가 게임/콘텐츠/글로벌 서비스 운영 맥락을 잘 잡는지
- FAQ/VOC/운영 가이드/서비스 운영을 역량 또는 후보로 잘 잡는지
- 일본 시장/심의·규제 대응 같은 문맥 의존 표현을 잘 잡는지

### 바티에이아이 / 커머스 데이터 솔루션 - 기술 기획자

현재 관찰:

- AWS/RAG/ERP/WMS/Python/SQL/ERD/API 등 skill 개선이 있었다.
- industry/domain/position은 null 이슈가 있었다.
- 이커머스 정산/재고/데이터 솔루션 맥락을 도메인으로 볼 필요가 있다.
- 고객사/제품명은 제외가 필요하다.

검증 포인트:

- AI가 이커머스 데이터 솔루션/정산/재고 맥락을 잘 잡는지
- SQL/ERD/API/Python/Pandas/프롬프트 엔지니어링을 적절히 분류하는지
- Bati CIS/COSRX/파마리서치 같은 고유명사를 제외하는지
- 개발 기술스택을 과도하게 skill로 추천하지 않는지

## 8. 품질 검증 절차

### Step 1. HR 페르소나 기대값 확정

- 데이터 정제 채팅방에서 공고 원문 기준 HR 페르소나 기대값을 먼저 작성한다.
- 기대값은 industry/domain/position, skills, competencies로 구분한다.
- 기대값을 이 품질 검증 문서에 기록한다.
- 현재 기대값이 없는 항목은 `사용자 입력 필요`로 표시한다.

### Step 2. 규칙 기반 결과 기록

- 현재 서비스의 `analysis_results`와 `review_items` 결과를 기록한다.
- 이미 문서에 있는 기존 재분석 결과를 우선 활용한다.
- 필요 시 사용자가 로컬에서 재분석 후 결과를 제공한다.

### Step 3. AI 추천 결과 기록

- 사용자가 openai mode로 POST `/runs`를 실행한다.
- history 상세 결과를 품질 검증 문서에 기록한다.
- AI 추천 단독 값과 오추출 후보를 정리한다.
- 이 문서 작성 작업에서는 API 호출을 수행하지 않는다.

### Step 4. 매칭률 계산

- 규칙 기반 단독 매칭률
- AI 추천 단독 매칭률
- 규칙 기반 + AI 추천 합산 매칭률
- AI 추천 오추출률

### Step 5. 개선 후보 분류

개선 후보를 아래로 분류한다.

- config 보강으로 해결 가능
- classification phase 3 코드 개선 필요
- AI prompt 개선 필요
- 제외/stopword 처리 필요
- dictionary_candidates로 장기 관리 필요

## 9. 목표 기준

1차 목표:

- 규칙 기반 + AI 추천 합산 매칭률 70% 이상
- AI 추천 오추출률이 과도하지 않을 것
- 특히 고유명사/전형 요건/불필요 기술스택 오추출이 반복되지 않을 것

| 결과 | 판단 |
|---|---|
| 합산 매칭률 70% 이상 + 오추출률 낮음 | AI 추천 실질 기여 확인 |
| 합산 매칭률 상승 + 오추출률 높음 | prompt/필터 개선 필요 |
| AI 단독 매칭률 낮음 | prompt 또는 모델 활용 방식 개선 필요 |
| 특정 산업에서만 낮음 | industry/domain config 또는 phase 3 개선 필요 |

## 10. 후속 작업 우선순위

1. AI 추천 품질 검증 수행
   - AI가 규칙 기반 classification을 실제로 보완하는지 먼저 수치로 확인해야 한다.

2. classification phase 3 개선
   - 품질 검증에서 반복 누락/오추출 패턴이 확인된 뒤 rule/config 개선 범위를 정한다.

3. 선택 반영 결과 표시 고도화
   - `applied_items_json` 기반으로 history 상세/비교 항목별 반영 상태를 더 명확히 표시한다.

4. dictionary_candidates 구조 설계
   - AI 추천과 선택 반영 결과의 후보 품질을 확인한 뒤 config 후보 관리 구조를 설계한다.
